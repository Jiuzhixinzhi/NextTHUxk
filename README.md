# OneTHU NextTHUxk — 下一代选课

`One App · One Identity · One Campus` · 选课工作台

</div>

> 清华本科生选课增强工具。在原选课页面叠加全屏工作台，提供随时查询、草稿编排、中签概率与学分模拟。

## 安装

> 🚀 校内访问 [git.tsinghua.edu.cn/gjl25/NextTHUxk](https://git.tsinghua.edu.cn/gjl25/NextTHUxk) 下载速度更快。
> 各渠道附件对照：`*.xpi` = Firefox 签名版（永久安装）；`*.zip` = Chrome / Edge / Firefox 手动加载通用包。
> Firefox 需要 **128+**（Tailwind 4 基线）。

### Firefox：下载 xpi 一键装（推荐，永久生效）

1. 从 [Releases](https://github.com/smartThise/NextTHUxk/releases) 最新版本下载 `nextthuxk-<版本号>.xpi`
2. 打开 Firefox，地址栏输入 `about:addons`，将 xpi 文件**直接拖入页面**
3. 完成安装——该包经 Mozilla 官方签名，无需开发者模式、重启浏览器不失效

**Firefox 更新方式**：发布新版本时扩展会在页面上弹出更新横幅（也可手动到 Releases 页查看）。下载新版 xpi 后同样拖入 `about:addons`，会自动覆盖升级并保留全部本地数据（草稿 / 缓存 / 配置）。无需先卸载旧版。

### Chrome / Edge：解压加载

1. 从 [Releases](https://github.com/smartThise/NextTHUxk/releases) 下载 `nextthuxk-<版本号>.zip` 并解压
2. 浏览器打开扩展管理页（Chrome: `chrome://extensions`，Edge: `edge://extensions`），开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择解压后的文件夹

> .crx 直拖方式已被 Chrome 收紧拦截，不再提供。更新时下载新 zip 解压**覆盖原文件夹**后回到扩展管理页点击「重新加载」即可；若出现新旧实例冲突等诡异问题，先移除旧版再重新加载。

## 使用

进入清华选课网站（zhjwxk.cic.tsinghua.edu.cn 或 zhjw.cic.tsinghua.edu.cn），右下角会出现 **OneTHU 品牌的启动按钮**（(One THU) 字标 + NextTHUxk）：

- 点击按钮 → 进入全屏工作台（首次使用会确认学期）
- 工作台内右上角「返回原系统」→ 收起工作台回到教务原页面

## 功能概览

### 课程浏览与搜索

- **随时查询架构**：不再整库预爬，搜索直达教务服务端按页取数，工作台秒开；关键词+筛选条件组合查询，分页条实时显示满足全部条件的页数与条数
- 全校课程目录搜索（按课名、课号、教师模糊匹配），**外校课全支持**：北大（PK/GPK）、北外（BW）等前缀课号可直接搜索、跳转定位，外校课真实上课时间自动解析进课表与冲突检测
- **可折叠筛选栏**：高级筛选收进按钮，课程展示区更大，展开状态自动记忆
- **搜索联想词**：边输边出候选，含 THU选课社区评分
- 按类型快速筛选：**必修 / 限选 / 体育 / 已选 / 我的队列 / 可选**
- 高级筛选：按**学分数**、**周几**、**第几大节**、通识课组、课程特色、本/研余量精确过滤
- **时间冲突筛选**：按与当前预览课表是否冲突过滤
- 每门课显示余量、竞争热度、各志愿排队人数

### 中签概率计算（预选阶段）

- 每门课程自动计算**所有合法选法的抽中概率**，红黄绿三色直观展示
- 概率模型基于志愿级联机制：容量按志愿优先级递减分配，结合各志愿报名人数估算中签率
- 课程卡片、草稿列表、预览课表均显示概率信息
- 修改课程类型或志愿号后概率实时刷新

### 课余量实时数据（抽签结果阶段）

- **实时课余量**：从教务系统获取所有课程的容量、剩余座位和排队人数
- **我的队列**：显示个人候补队列，包含队列排名和总排队人数（如「排队第121名 / 共185人」）
- 课程卡片显示余量/排队/排入希望值，替代预选阶段的概率显示
- **志愿数据按教务检查点自动同步**（8:00 / 12:00 / 16:00 / 20:00），缓存信息条显示下次同步时间，无需手动刷新

### 时间冲突检测

- 所有课程卡片自动检测与当前预览课表（正选/草稿）的时间冲突
- 冲突信息直接显示在卡片上（如「⚠ 冲突: 周三 3-4节 数据结构」）
- 支持筛选「仅无冲突」或「仅冲突」课程

### 草稿编排（核心）

草稿 = 命名课表方案（至多 5 份），**可直接编辑**：直接改类型/志愿、删除、改名，改动即时保存。任意时刻恰有一份**活跃草稿**是编辑目标：

- 课程卡「**加入草稿**」：并入活跃草稿，**不提交正选变更**，并**硬阻断新的时间冲突**（对活跃草稿 + 自定义占用做区间检测；会撞课时拒绝加入并提示具体冲突课程与时段）
- 空草稿自动创建；「已选载入」把当前已选整表并入活跃草稿，以现有课表为底稿继续编排
- 草稿列表可展开查看/调整全部课程、每门课显示实时概率（预选）或余量排队（课余量）
- 草稿可一键设为活跃、预览课表、导出 JSON 分享、导入并入
- **冲突是合法存在的**：导入/载入进来的数据允许含冲突（草稿面板标红显示）；仅「加入草稿」主路径硬阻断
- **留下直接正选变更的入口**：卡片上的**退选 / 退队 / 志愿调整**仍在；其余正选变更一律走「提交选课」

### 选课 & 提交选课

- **提交选课**（差量对齐）：与当前已选重合（课序、志愿、类型均一致）的课程**保持不动**，只退选多余、补选新增；提交前以精确数字确认（保留 X · 退选 Y · 新选 Z）
- 课程类型选择遵守选课规则：必修课可走必修/限选/任选通道；限选课可走限选/任选；任选课只能任选；体育课只能体育（航空体育等按规则排除）
- 已选课程可**调整志愿顺序**（▲▼），系统自动校验志愿名额上限（必修/限选/任选：1 志愿 1 门、2 志愿 2 门；体育 1/2 志愿各 1 门；3 志愿不限）
- 操作后实时刷新选课状态；每步校验不假成功

### 课表预览

- 自动生成**周课表**视图（周一至周日 × 时间轴分道布局，含自由钟点/自定义占用）
- 时间冲突标红显示；课块可切换查看**当前已选 / 活跃草稿 / 其它草稿**（segmented 切换）
- 课表单元格显示课程名称、教师、起止钟点、外校来源徽标与概率/排队状态
- **直接在课表上操作**：悬停 ✕ 可退选（已选视图）、从草稿移除（草稿视图）、删自定义占用
- **点击课块 → 左侧定位**：自动按课号精确搜索、补齐全量并平滑滚动高亮 1.8s
- **自定义时间占用**：「＋ 添加占用」登记社团例会等课外活动（紫色显示），本地保存并**参与全部冲突检测**
- 草稿预览课表按概率着色（预选阶段绿/橙/红；课余量阶段显示余量/排队人数）

### 学分中签模拟

- 活跃草稿 / 任意草稿一键打开弹窗：按每门课实时中签概率（身份/志愿）用精确动态规划算出总学分概率分布——期望学分、最可能总分、至少达到目标学分的概率，附直方图与累计概率表
- 无数据 / 已满排队的课可在弹窗内手动填覆盖（实时取值 / 手动覆盖双模式 tab，改过标「改」角标）

### 培养方案检测

- 查看所有培养方案课组及完成进度（覆盖正选 + 全部草稿）
- 特殊规则：体育课互认；英语(3) 可由进阶读写或第二外国语替代；英语(1)(2) 不可由第二外国语替代

### 一键备份

- 顶栏「备份」下拉：统一导出/导入 json（全部草稿 + 自定义占用），跨设备恢复编排现场
- 导入按课班 / 草稿名**智能合并**，不覆盖既有数据；兼容旧版备份（v1 暂存并入活跃草稿）

### THU选课社区评价（thubook.help）

- 课程卡片显示**社区评分徽章**（★4.6·12评），有点评的课才出现，点击看全部点评
- 点评正文**实时拉取**（星级 / 给分档位 / 时间 / 全文），永远最新
- 一键跳社区课程页或**去写点评**，反哺社区
- 全部流程 fail-soft：社区数据加载失败不影响任何选课功能

### 自动更新

- 定期检查 GitHub Releases 是否有新版本
- 发现更新时在顶部显示提示横幅；也可手动点击「检查更新」

### 学期管理

- 自动从教务系统 URL 检测当前选课学期
- 支持手动切换学期（点击顶栏学期标签）
- 切换后自动清空缓存并重新拉取数据

## 数据与隐私

- 选课操作走原系统表单提交，与手动操作完全等价
- 个人数据（草稿等）全部存储在浏览器本地
- 扩展代码中不包含任何个人数据
- 课程目录和志愿数据有缓存机制：
  - 课程目录：**随时查询**——按需向教务服务端取数，热门搜索结果会话内缓存
  - 志愿排队数据：每日 **8:00 / 12:00 / 16:00 / 20:00** 教务检查点自动同步
  - 已选课程：每次打开工作台实时获取

## v3.0.0 重构（Svelte 5 + TS + Tailwind 4）

> 一次性大型重构（2026-09）：原 vanilla JS + `NX.*` 命名空间 + manifest 脚本注入顺序 全部移除。目标技术栈 Svelte 5 runes + TypeScript + Tailwind CSS 4；构建 Vite 双入口（content 单 IIFE + popup ESM）。

- **消除 god class**：`NX.state` 与几十个字段拆为按域 stores（session / search / drafts / volunteer…），显式 import 依赖图
- **消除隐式时序**：数据层不再直接调渲染函数——全部改为改 store 状态，UI 由响应式自动跟随；`volNeedsRefresh` 跨文件覆盖消亡
- **消除手动 HTML / 手动视图模型**：全部 innerHTML 拼接 → Svelte 模板；缓存失效计数器（selVersion/poolVersion/invalidatePreview）→ `$derived`；预览模式从「label 字符串回读」改为显式 `previewTarget`；筛选状态源不再是 DOM
- **草稿模型取代暂存**：草稿可直接编辑 + 活跃草稿；卡片「加入草稿」不提交正选、硬阻断新时间冲突；「保存草稿清空暂存/载入暂存」等动作删除
- **AI 特性移除**：AI 排课 / AI 搜索 / AI 配置 / 年级引导全部删除（评分徽章与排序保留）
- **UI**：液态玻璃配方迁入 `@theme` 令牌；prompt()/confirm() 全部替换为玻璃模态框
- Firefox 兼容底线 115 → **128**

### 行为保真不变量（未改变）

GBK 双向契约（"UTF-8 直发教务 0 行"实锤至今有效）· 风暴护栏（1 页精确课号 / ≤25 全量 / >25 探 5 / 5 并发 + 30ms 错峰 / p_kch 4 门/次）· 一次性 token 链 + pollUntil 不假成功 · reviews fail-soft + CC BY-NC 署名 · WebVPN 前缀 + AES-CBC 站点识别（key 勿改）· 检查点 8/12/16/20 志愿窗口缓存 · knote/zyCache/外校钟点解析 · 培养方案特殊规则。

## 开发

```bash
pnpm install
pnpm build              # 双构建：content.js（IIFE，JS+CSS 全内联注入 Shadow DOM）+ popup.html + manifest/icons
pnpm build --watch      # 监听构建（dev：改完 5s 内重新加载扩展即可）
pnpm test               # vitest：时间/冲突/概率/GBK/差量/方案覆盖
pnpm check              # svelte-check --fail-on-warnings
```

加载产物：`chrome://extensions` / Firefox `about:debugging` → 加载 `dist/` 目录。

## 文件结构

```
├── manifest.json            # 浏览器扩展配置 (Manifest V3，Firefox ≥128)
├── vite.content.config.ts   # content 单 IIFE 构建（CSS 以 ?inline 注入 Shadow DOM）
├── vite.popup.config.ts     # popup ESM 构建
├── scripts/build.mjs        # 发布构建编排（双构建 + manifest/icons 拷贝）
├── src/
│   ├── content/             # main.ts 入口 + App.svelte + 全部组件 + app.css（玻璃令牌）
│   ├── popup/               # 扩展弹出页（Svelte）
│   └── lib/
│       ├── core/            # 常量/工具
│       ├── net/             # GBK 编码表 + 响应解码 + HTTP + 并发分页抓取器
│       ├── site/            # WebVPN 站点识别
│       ├── storage/         # 存储封装（Chrome/Firefox 双形态）+ knote 时间缓存
│       ├── domain/          # 纯函数域逻辑（时间/冲突/概率/草稿/方案覆盖…）
│       ├── api/             # 服务端 IO（搜索/记录/志愿/写 API）
│       ├── reviews/         # THU选课社区评价层
│       ├── update/          # 版本更新检查 + 检查点窗口
│       └── stores/          # Svelte 5 runes 状态与编排
└── tests/                   # vitest
```
