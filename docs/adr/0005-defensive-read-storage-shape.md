# 0005. 防御读自愈的存储形状变更可豁免 DATA_VER 递增

- 状态：已接受
- 日期：2026-09-17
- 相关：`AGENTS.md` 硬性规则 1 · `src/lib/stores/zy.svelte.ts`（`zyCacheHydrate`/`resolveCourseZy` 持久化）· `src/lib/core/constants.ts`（`DATA_VER`）

## 背景

硬性规则 1 要求「存储结构变更递增 `DATA_VER`（不匹配即整体清缓存）」。但存在一类变更：**新形态可被旧数据安全判别并丢弃、且首次写入即覆写**。`zyCache` 即先例——v3 改写期丢了水合读取，恢复时把存储形状从裸 map 收紧为 `{sem, map}`（学期隔离）；若为此递增 `DATA_VER`，会连带清空已选/方案/志愿等全部静态缓存，代价与收益不成比例。

## 决策

同时满足以下三点时，**可**不递增 `DATA_VER`，改以「防御读自愈」处理，并在此处登记先例：

1. **防御读**：读取处判形态（`Array.isArray`/`typeof`/版本字段），旧形态或异学期直接弃用，不抛错；
2. **首写覆写**：下一次正常持久化即写新形态（无需迁移代码）；
3. **失败可退**：弃用后功能降级为「缓存未命中」（重新拉取/重问），无正确性损失。

**不满足任一条件**（如旧形态会被误读、需保留跨版本用户数据、丢弃不可恢复）时，仍必须递增 `DATA_VER`。

## 后果

- 已登记先例：`zyCache` 裸 map → `{sem, map}`（不递增 DATA_VER；`zyCacheHydrate(sem)` 异学期/异形态即弃）。
- 评审口径：此后「形状变更未递增 DATA_VER」不再默认是缺陷，需对照上述三条；条款本身不变更硬性规则 1 的主体要求。
